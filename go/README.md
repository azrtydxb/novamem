# novamem-server (Go)

The Go port of `packages/server`. Same env-var contract, same HTTP
surface, same Postgres schema — see
[the migration spec](../docs/superpowers/specs/2026-08-13-go-migration-design.md)
and [the parity audit](../docs/architecture/go-parity-audit.md).

## Building

```sh
go build ./cmd/novamem-server        # needs the embedded assets present
```

Two build artifacts are **checked in** because `go:embed` cannot reach
outside the module directory:

| Path | Source | Regenerated by |
|---|---|---|
| `internal/httpapi/openapi.json` | `docs/api/openapi.json` | `packages/server`'s `docs:api` generator (CI drift gate) |
| `internal/httpapi/admin-ui/` | `packages/admin-ui/dist` | `./scripts/sync-admin-ui.sh` |

### Admin dashboard

The dashboard SPA is served from the binary under `/admin/*`. After any
change to `packages/admin-ui`:

```sh
pnpm --filter @azrtydxb/novamem-admin-ui build
go/scripts/sync-admin-ui.sh
```

The sync drops `*.woff` (every face also ships as `woff2`, which every
browser since ~2016 prefers), taking the committed copy from 2.1 MB /
108 files to 1.3 MB / 65 files. `go/Dockerfile` runs both steps, so a
container build never depends on the committed copy being fresh.

`NOVAMEM_ADMIN_DASHBOARD=0` registers no `/admin` routes at all, exactly
as in the TS server.

## Deliberate divergences from `packages/server`

Everything else is transcribed behaviour; these are the choices worth
knowing about.

* **Rate limiting** (`NOVAMEM_RATE_LIMIT_PER_MINUTE`, default 600) runs
  *before* auth, so unauthenticated traffic is counted too — in the TS
  server the auth hook 401s ahead of the limiter, which leaves exactly
  the traffic a limiter is for uncounted. Keys are X-Forwarded-For aware
  (TS keys on the socket address, which puts every caller behind an
  ingress in one bucket). Counters are in-memory and per-replica, like
  `@fastify/rate-limit`'s default store and like the existing quota
  limiter: N replicas means an effective ceiling of N × max.
* **`/api/auth/*`** implements the five endpoints the dashboard calls
  (`admin/list-users`, `admin/create-user`, `admin/set-role`,
  `admin/remove-user`, `change-password`) plus sign-in/sign-out/
  get-session. Better Auth's other routes are not served. A POST with no
  `Origin` header at all is accepted (Better Auth 403s it); a POST with
  an untrusted `Origin` is refused, as everywhere else in this server.
* **204 preflight responses carry no `Content-Length: 0`** — net/http
  suppresses it on 204 by design.
* Static assets are served with Go's `text/javascript` rather than
  `@fastify/static`'s `application/javascript`; both are correct.
